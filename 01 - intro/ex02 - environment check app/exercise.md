# Lesson 02 Take-Home Exercise

## Title
Environment Verification and Troubleshooting Reflection

## Purpose
This exercise reinforces lesson 02 by asking you to document your setup status, explain your testing workflow, and think through common troubleshooting steps before lesson 03.

## Before You Start
Use these lesson-02 reference files:
- [setup-checklist.md](setup-checklist.md)
- [setup-status-tracker.md](setup-status-tracker.md)
- [troubleshooting-checklist.md](troubleshooting-checklist.md)

Helpful lesson-02 terms:
- **verified**: your Expo verification app runs on an emulator or physical device
- **partial**: some setup steps are complete, but one major step still remains
- **blocked**: you cannot continue without additional help, permissions, or a different device path
- **verification path**: the way you tested the app, such as Android emulator with a development build
- **Expo server**: the local development server started by `npm run start` or `npx expo start`

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 page total.

## Tasks
### Part 1: Setup Status Snapshot
Report your current status:
- `verified`
- `partial`
- `blocked`

Then include:
- which verification path you used or attempted
- the furthest successful step you completed
- the next required action

### Part 2: Workflow Explanation
Write 4 to 6 sentences explaining:
- why lesson 02 focuses on verification instead of only installation
- one difference between Expo Go and a development build
- one difference between emulator testing and physical-device testing
- why the course uses a shared verification app and setup baseline before building new apps

### Part 3: Troubleshooting Reasoning
Choose two common issues from [troubleshooting-checklist.md](troubleshooting-checklist.md).

For each issue:
- name the likely failing step
- describe one small troubleshooting action you would try first
- explain what result would tell you whether that action helped

## Success Criteria
Strong submissions will:
- report setup progress clearly and honestly
- distinguish between verification path and setup status
- show step-based troubleshooting instead of random guesswork
- use lesson-02 terms correctly

## Optional Extension
If you reached `verified`, add one screenshot of the verification app running on your chosen device path.
